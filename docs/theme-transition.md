# 1.2.3 主题渐变、横纹修复与分段分页

1.2.3 修正了渐变中位图背景与原生控件的颜色取整差异：例如混合比例为 35% 时，原生面板为 RGB 113/113/115，而旧位图为 112/112/114，相邻平面会出现细微条带边界。现在两者都使用同样的四舍五入计算，并回归检查了卡片整列平面像素与原生配色完全一致。

渐变位图改用缓存的索引 PNG 调色板更新，避免在已显示图片上逐帧执行 ImageTk.paste 或整幅位图混合。按钮、输入框和进度条扩大了内部平铺块，同时保留原有控件请求尺寸，减少 Windows 小块平铺的重绘开销。

“生成设置 / 角度筛选 / 运行日志”采用与主题选择器一致的圆角轨道和单一滑块，支持从当前位置和速度反向选择。页面立即响应选择；滑块移动不会延迟输入或清空各页数据。鼠标移出后释放可取消，左右键和 Home/End 可选页，Ctrl+Tab / Ctrl+Shift+Tab 继续循环分页，Ctrl+Enter 继续用于开始生成。减少动态效果时直接切换，关闭窗口时清理动画及变量监听。

此前只有 Dark / Light 选中块滑动，主体切换时立即替换 ttk 主题，标题栏也只切换 Windows 深浅标志，因而会出现突变与颜色不同步。

现在参考 ACT-WBEX-Updater 的 ThemeFade：使用一个可中断的临界阻尼过渡混合配色，主体、文字、按钮、输入框、进度条、卡片、拖入区、日志和原生标题栏都使用同一帧颜色。响应参数为 0.4 秒；本机实际完整过渡约 0.6 秒，实际时长会随系统负载变化。快速反向切换保留当前亮度及变化速度，不先跳到终点。

Dark、Light 和过渡所需的 ttk 样式及位图预先缓存。每帧在已有图片中混合颜色，不重新创建控件、字体、主题或 Tk 图片，窗口尺寸、参数、当前页面、日志、拖入反馈及处理进度均保持不变。

Windows 11 的 DWM 标题栏背景和文字颜色逐帧明确设置为当前主体背景及文字颜色；标题栏按钮的深浅模式按当前亮度判断。对不支持自定义标题栏颜色的系统，保留原生深浅模式，并缓存不支持结果，避免每帧重复调用无效属性。旧系统标题栏可能仍以深浅两档切换，主体渐变不受影响。

默认启动 Dark，无启动闪白。关闭 Windows 客户端区域动画后，主体和按钮都立即切换；键盘选择也立即完成。Ctrl+Enter 保持开始生成的快捷键，按钮获得焦点后不会拦截它。关闭窗口时清理待执行的渐变回调。

## 验证

自动测试覆盖中间配色、不分配新帧资源、保留输入及处理状态、快速反向过渡、缓存的终点配色不被污染、减少动态效果、标题栏颜色参数及旧系统降级、关闭窗口时清理回调。

本机 Windows 11 另外检查了 0%、20%、40%、60%、80%、100% 六个阶段的实际屏幕像素，原生标题栏与主体背景均匹配。验证工具只截取本程序窗口：

```powershell
python tools/verify_theme_transition.py --output build/theme-fade-qa
```

截图和 `verification.json` 保存在 build 目录，不上传个人桌面背景或本地 QA 输出。
